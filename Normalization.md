Database Normalization

Normalization is a process used in database management to organize data into different tables in a proper way. The main purpose of normalization is to reduce duplicate data, avoid data inconsistency, and make the database easier to manage. In this project, normalization is used in both the Student Management System and Employee Management System. The Student database contains tables such as `department`, `student`, `course2`, `enrollment`, and `faculty`, while the Employee database contains `employee`, `attendence`, and `salary` tables. Instead of keeping all the information in one large table, the data is divided into different tables and connected using primary keys and foreign keys.

First Normal Form (1NF)

First Normal Form means that every column should contain only a single value and there should not be any repeating groups in a table. In the Student database, the `student` table contains `roll_no`, `name`, and `marks`, where each column stores a single value for every student. Similarly, the `department` table stores one department ID and one department name in each record. The same concept is followed in the Employee database. The `employee` table stores employee ID, first name, and last name separately. The `attendance` table stores attendance ID, work hours, and employee ID, while the `salary` table stores salary, work hours, and employee ID. This structure follows the basic idea of 1NF because the data is stored in individual fields instead of storing multiple values in a single column.

Second Normal Form (2NF)

Second Normal Form means that the table should already follow 1NF and there should be no partial dependency on a part of a composite primary key. This is mainly important when a table has a composite primary key. In the Student database, the `enrollment` table has a composite primary key consisting of `roll_no`, `course_id`, and `semester`. The grade belongs to the particular combination of a student, course, and semester. Student information is kept in the `student` table and course information is kept in the `course2` table instead of repeating those details inside the enrollment table. This helps reduce unnecessary duplication. In the Employee database, the main employee table uses `employee_id` as its primary key, so there is no partial dependency because the primary key consists of only one column. Attendance and salary information are also kept separately from the basic employee information.

Third Normal Form (3NF)

Third Normal Form means that the table should already be in 2NF and non-key columns should depend directly on the primary key rather than depending on another non-key column. In the Student database, department information is stored separately in the `department` table. The `course2` table contains `course_id`, `course_name`, and `dept_id`, where `dept_id` connects the course with its department. The department name is not repeatedly stored in the course table. Similarly, the `faculty` table uses `dept_id` as a foreign key to connect faculty members with their department. In the Employee database, employee details are stored in the `employee` table, while attendance and salary details are stored in separate tables. This prevents the same employee information from being unnecessarily repeated in different records and makes the database easier to update.

Boyce-Codd Normal Form (BCNF)

Boyce-Codd Normal Form, or BCNF, is a stronger version of Third Normal Form. A table is in BCNF when every determinant is a candidate key. In simple terms, if one column determines another column, the column responsible for that determination should be a key. In the Student database, `dept_id` is the primary key of the `department` table and determines the department name. Similarly, `course_id` determines the course details in the `course2` table. In the Employee database, `employee_id` determines the employee's first name and last name. The given database does not have complicated dependencies that require a separate BCNF decomposition, but the use of primary keys and properly separated tables follows the basic idea of BCNF.

Fourth Normal Form (4NF)

Fourth Normal Form deals with multivalued dependencies. It is useful when one record can have multiple independent values of different types. For example, if an employee has multiple skills and multiple languages, storing both skills and languages in the same table can create unnecessary combinations of data. Instead, separate tables can be created for employee skills and employee languages. In the Employee database, employee information, attendance information, and salary information are already separated into different tables. Similarly, in the Student database, student, course, department, faculty, and enrollment information are stored separately. The current database does not contain a complicated multivalued dependency, so a special 4NF decomposition is not required.

Fifth Normal Form (5NF)

Fifth Normal Form is also known as Project-Join Normal Form. It deals with more complex relationships where information can be divided into smaller tables and later joined together without producing incorrect or unnecessary records. In the Student database, tables such as `student`, `enrollment`, `course2`, and `department` are connected through primary keys and foreign keys. This allows information to be stored separately and combined when required using SQL JOIN operations. For example, student details can be joined with enrollment and course details to find which course a student has taken. In the Employee database, the `employee`, `salary`, and `attendence` tables can also be joined using `employee_id`. The current project is not complex enough to require a specific 5NF decomposition, but the table structure demonstrates the basic idea of keeping related information separate and joining it when needed.

Overall, normalization helps make both the Student and Employee databases more organized and easier to maintain. The Student database separates department, student, course, faculty, and enrollment information, while the Employee database separates employee, attendance, and salary information. The first three normal forms are the most directly applicable to the current database because they remove repeating data, reduce partial dependencies, and avoid unnecessary dependencies. BCNF, 4NF, and 5NF are more advanced forms that become important when the database contains more complicated relationships. By using primary keys, foreign keys, and separate tables, the database becomes easier to update, reduces duplicate information, and maintains better data consistency.
